# Optional landing-page measurement

This release does not enable any Google provider by default. Both environment variables should stay unset until the owner approves the specific Google property and its configuration.

- Set **one** production-only variable: `LANDING_ANALYTICS_GTM_ID` (a `GTM-…` container) or `LANDING_ANALYTICS_GA4_ID` (a Google Analytics `G-…` measurement ID). The site fails closed when both or an invalid ID are supplied. Redeploy to apply changes because the layout can be prerendered.
- Direct GA4 is simpler for a single landing view. For GTM, dedicate a web container and keep just the Google tag and a GA4 page-view event triggered by `maa_landing_view`. Disable the Google tag's automatic page view (set `send_page_view` to `false`), map the event's `page_location`, `page_referrer`, and `page_title` to the same-named data-layer fields, and require analytics consent. Ensure the Google tag has initialized before firing the custom page-view tag. Do not use All Pages for the page-view event, custom HTML, advertising tags, a linker, arbitrary click/form/history triggers, or user data variables.
- In the GA4 web stream, disable enhanced measurement and Google Signals. Do not add advertising links, cross-domain linking, remarketing, or user-provided data. Confirm that only the intended public-page measurement is collected; the opaque-origin iframe intentionally does not provide normal first-party storage, and browsers may block delivery. Do not weaken iframe isolation to get delivery.
- Consent is basic mode: no Google script or frame without opt-in. Ad storage, ad personalization and ad-user-data signals remain denied. Tracking is restricted to the canonical `https://agent.bifavia.uz/` public root, without query or hash. The sandboxed, browser-generated Blob frame does not have access to the app page or storage, loads with no referrer, and supplies only a fixed page location and title plus an empty analytics referrer. Private routes, supplier token links and account data should never be measured. An opt-out in `/cookies` removes the frame and blocks future collection.
- Verify with a fresh browser session: no network request to a Google tracking host before choice or after choosing “Faqat zaruriylari”; one page view upon acceptance; no query/referrer/account data in the sent measurement; none on a private page, preview host, or a landing URL with parameters/fragment. Test revisiting `/cookies` to withdraw and then returning to the homepage. Assert the sandbox and document CSP, and confirm the page view in the owner’s GA4 Realtime/DebugView. Leave production IDs unset if any check fails. No third-party connection is proven from local unit tests.

Reference: [Google basic consent mode](https://developers.google.com/tag-platform/security/concepts/consent-mode), [consent mode implementation](https://developers.google.com/tag-platform/security/guides/consent), [GA4 enhanced measurement](https://support.google.com/analytics/answer/9216061).
